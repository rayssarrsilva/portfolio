How I work

The same process in every project, shown here with links to the real documents from Moringa.

  1. Discover

    A product brief, proto-personas and a backlog with acceptance criteria before any screen. Moringa brief · backlog.

  2. Design

    User journeys in FigJam, wireframes, then high-fidelity screens built only with components from my design system. Figma file.

  3. Build in small steps

    Small pull requests, Conventional Commits checked by commitlint, TypeScript in strict mode and ESLint with zero warnings allowed.

  4. Test at every level

    Unit tests, integration tests against a real Postgres in memory, and end-to-end tests on mobile and desktop with axe in both themes.

  5. Gate every merge

    GitHub Actions runs Lighthouse CI, an OWASP ZAP scan and CodeQL on each pull request; Dependabot keeps dependencies current.

  6. Run a QA cycle

    After release: test plan, traced test cases, exploratory sessions, bug reports and a summary. Test plan · bug reports · summary.
